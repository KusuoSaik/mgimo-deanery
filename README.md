# Цифровой деканат будущего МГИМО

Мобильный first-портал студента, который объединяет повседневные академические сервисы, обращения в деканат и персонального ИИ-помощника в одном интерфейсе. Проект создан как демонстрационный прототип концепции цифрового деканата: он показывает пользовательские сценарии и визуальную модель продукта, а данные и часть интеграций пока работают в mock-режиме.

## Суть продукта

«Цифровой деканат будущего МГИМО» сокращает путь студента от вопроса до действия:

- студент видит ближайшее занятие и важные уведомления на главном экране;
- проверяет расписание и текущие результаты обучения;
- рассчитывает прогноз по БРС перед экзаменом;
- оформляет справки и другие обращения через единый центр заявок;
- получает от ИИ-ассистента ответ с возможностью сразу перейти к целевому действию;
- управляет профилем, приватностью и демонстрационными данными.

Интерфейс спроектирован по принципу mobile-first для экрана шириной примерно 375–430 px. В приложении используются русский язык, карточная навигация и единая визуальная система МГИМО с тёмно-синими и академическими золотыми акцентами.

## Ключевые возможности

### Расписание

- просмотр занятий по дням недели;
- автоматическое определение текущего дня и типа учебной недели;
- фильтрация по типу занятия;
- отображение времени, дисциплины, преподавателя, корпуса и аудитории;
- карточка ближайшего занятия и обратный отсчёт на дашборде.

### БРС и калькулятор академического прогноза

- экран «Зачётка и БРС» со списком дисциплин;
- текущие баллы, максимальный балл и статус по предмету;
- визуальный прогресс по каждой дисциплине;
- калькулятор прогноза: студент задаёт предполагаемые баллы за экзамен и получает итоговый результат и ориентир по оценке;
- средний рейтинг БРС в профиле и на главном экране.

### Центр заявок и ЭЦП

- создание заявки в деканат;
- категории: справки, военкомат, финансы и материальная помощь, академические вопросы;
- выбор формата получения: электронный документ с ЭЦП в PDF или бумажный оригинал в деканате;
- поиск и фильтрация заявок по статусу;
- статусы жизненного цикла: «Создано», «Проверка деканатом», «Подписано ЭЦП», «Готово»;
- быстрый переход к заявкам с дашборда и из ИИ-ассистента.

### Actionable ИИ-ассистент

Ассистент не ограничивается справочным ответом, а предлагает следующий шаг:

- учитывает контекст текущего пользователя, БРС и заявок;
- отвечает на вопросы об академических данных и обращениях;
- распознаёт сценарий запроса справки;
- предлагает оформить электронную справку с ЭЦП в один клик;
- позволяет открыть центр заявок непосредственно из диалога.

В текущем прототипе ответы имитируются на клиенте. Подключение реальной LLM, RAG по регламентам МГИМО и серверных action-инструментов является следующим этапом развития.

### Защита ПДн: 152-ФЗ, маскирование и 2FA

Концепция продукта предусматривает защиту персональных данных на всех критичных шагах:

- двухфакторный вход после ввода логина и пароля;
- режим приватности профиля;
- маскирование и обезличивание ФИО, паспортных данных и СНИЛС перед передачей контекста ИИ;
- обработка данных внутри защищённого контура организации;
- минимизация передаваемых ИИ данных и аудит действий ассистента.

В демонстрационной версии реализованы экран входа с отдельным шагом 2FA и переключатель приватности с пояснением механики обезличивания. Это продуктовая демонстрация, а не заключение о соответствии требованиям 152-ФЗ: для промышленного запуска потребуются серверная архитектура, модель угроз, регламенты, журналирование, управление доступами и подтверждение соответствия ответственными подразделениями.

## Технологический стек

- **Frontend:** React 19, TypeScript 6, Vite 8.
- **Стилизация:** Tailwind CSS 4 через официальный Vite-плагин.
- **Иконки:** lucide-react.
- **Состояние прототипа:** React hooks и localStorage браузера.
- **Данные:** типизированные mock-объекты в [`src/mockData.ts`](src/mockData.ts) и контракты в [`src/types.ts`](src/types.ts).
- **Проверка качества:** ESLint, TypeScript build и Vite production build.
- **Текущий формат:** клиентское SPA без backend, базы данных и реальной интеграции с ЭЦП, ЕСИА, расписанием или LLM API.

Основные экраны приложения находятся в [`src/components/`](src/components/): дашборд, расписание, БРС, заявки, ИИ-ассистент, вход и профиль. Точка сборки приложения — [`src/App.tsx`](src/App.tsx), общие стили — [`src/App.css`](src/App.css) и [`src/index.css`](src/index.css).

## Пайплайн разработки через ИИ-агентов

Мы используем агентный подход как управляемый цикл разработки, а не как замену инженерной проверке:

1. **Формулировка задачи.** Product- или UX-агент превращает идею в пользовательский сценарий, критерии готовности и ограничения.
2. **Разведка кодовой базы.** Аналитический агент изучает структуру проекта, типы, существующие компоненты и дизайн-систему; изменения без контекста не принимаются.
3. **Проектирование.** Архитектурный агент предлагает границы компонента, состояния, контракты данных и сценарии ошибок.
4. **Реализация.** Кодовый агент вносит небольшие целевые изменения с учётом правил проекта, mobile-first и типизации.
5. **Проверка.** Отдельный агент проводит code review: проверяет доступность, UX, безопасность, регрессии и соответствие требованиям.
6. **Автоматические проверки.** Запускаются линтер, TypeScript-проверка и production-сборка.
7. **Ручная приёмка.** Команда проверяет сценарии в браузере, включая мобильный viewport, и сверяет результат с критериями готовности.
8. **Итерация.** Замечания превращаются в новые небольшие задачи, а изменения проходят тот же цикл повторно.

Для синхронизации технических правил и визуального направления используются [`.cursorrules`](.cursorrules), типовые контракты и единые компоненты. Любой результат ИИ считается черновиком до прохождения тестов и ревью человеком.

## Запуск проекта

### Требования

- Node.js 20 или новее;
- npm 10 или новее;
- macOS, Linux или Windows с установленными Node.js и npm.

### Установка зависимостей

Из корневой директории проекта выполните:

```bash
npm install
```

### Режим разработки

```bash
npm run dev
```

После запуска Vite выведет локальный адрес, обычно [`http://localhost:5173`](http://localhost:5173). Откройте его в браузере. Для проверки mobile-first интерфейса включите эмуляцию мобильного устройства в DevTools.

### Проверка перед коммитом

```bash
npm run lint
npm run build
```

`npm run lint` проверяет исходный код ESLint, а `npm run build` запускает проверку TypeScript и собирает production-версию в каталоге `dist`.

### Предпросмотр production-сборки

```bash
npm run preview
```

Команда запускает локальный сервер для проверки уже собранной версии приложения.

## Демо-данные и ограничения прототипа

- Данные пользователя, расписания, БРС, уведомлений и заявок находятся в [`src/mockData.ts`](src/mockData.ts).
- Новые заявки и уведомления сохраняются в localStorage текущего браузера.
- Кнопка сброса демо-данных в профиле очищает локальное состояние и возвращает начальный сценарий.
- Вход и 2FA демонстрируют UX-поток, но не выполняют реальную проверку учётной записи.
- ЭЦП, маскирование ПДн, 152-ФЗ и ИИ-интеграция представлены как продуктовый сценарий и требуют backend-реализации перед использованием в production.

## Направления развития

1. Подключить backend, СУБД и реальные роли: студент, сотрудник деканата, администратор.
2. Интегрировать расписание, ведомости, СКУД/учебные системы и сервис электронных подписей.
3. Реализовать серверную аутентификацию, 2FA, RBAC, аудит и управление сессиями.
4. Добавить защищённый шлюз ИИ, RAG по внутренним регламентам и каталог разрешённых действий.
5. Провести threat modeling, DPIA/оценку обработки ПДн и нагрузочное тестирование.
6. Подготовить CI/CD, e2e-тесты и мониторинг production-среды.
