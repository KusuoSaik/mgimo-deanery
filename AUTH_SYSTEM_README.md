# Серверная авторизация демо-кабинета

Авторизация конкурсной версии работает через Vercel Functions.

1. `POST /api/auth` принимает логин и пароль.
2. Сервер ищет аккаунт в seed-данных и проверяет пароль через `scrypt`.
3. После успешного входа сервер устанавливает подписанную `HttpOnly` cookie сессии.
4. Клиент получает только публичный профиль и учебные данные текущего пользователя.
5. Заявки и уведомления изменяются через `/api/student`; API проверяет владельца по сессии.
6. Выход удаляет серверные cookies.

Тестовые аккаунты находятся в `README.md`. Все данные вымышлены.

## Что проверено

- пароль и хеши отсутствуют в клиентском bundle;
- запрос к `/api/student` без сессии получает `401`;
- попытка изменить заявку с чужим идентификатором получает `404`;
- обновление страницы сохраняет текущую сессию и состояние заявки;
- `/api/chat` игнорирует профиль, присланный браузером, и берёт его из серверной сессии.

Для продакшена нужно задать `SESSION_SECRET`. При деплое на Vercel без этой переменной сервер намеренно не запускает auth-функции.
