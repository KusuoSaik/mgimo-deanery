# Пакет 005: исправления после проверки

База пакета: `481c1b8` (`main` и `feat/student-hub` на момент проверки). Общий контракт `src/types.ts` не изменён. Визуальная система, карточки и мобильная навигация сохранены.

## Что изменилось

- Каждое действие повторяется на свежей версии состояния при конфликте PostgreSQL. Старые снимки больше не объединяются поверх новых. Ответ содержит фактически сохранённые данные.
- Создание возвращает `createdRequest` с точным ID. Повтор одной операции с тем же `operationId` не создаёт вторую заявку. Переход этапа проверяет `expectedStage`.
- Чтение базы во всех API защищено обработчиком ошибок; недоступность состояния возвращает JSON с HTTP 503. Сбой проверки сессии показывается отдельным экраном с повтором.
- Очередь браузерных сохранений связана с конкретным входом. Выход отменяет запросы и задания очереди. Сервер дополнительно проверяет `ownerId`. Сброс чата меняет поколение истории и отклоняет старые записи.
- ИИ использует PostgreSQL для общего счётчика и временных слотов между экземплярами Vercel. Транзакционная advisory-блокировка защищает выделение слота. Слот истекает после сбоя процесса. В памяти остаётся только локальный fallback.
- После 429 провайдера общий cooldown в PostgreSQL учитывается всеми экземплярами; при отсутствии Retry-After используется минута ожидания.
- Повторы учитывают тип ошибки, Retry-After и бюджет времени. Неверный ключ или модель не повторяются. Пустой ответ не считается успешным. UI показывает причину сбоя.
- Язык переключает элементы управления существующих экранов, форм, окон и входа; вымышленные учебные записи, ФИО и пользовательский текст сохраняют исходный язык. Язык ответа ИИ передаётся серверу.
- Настройки доступности применяются на уровне приложения, сохраняются при навигации и учитываются JS-анимациями. Крупная навигация занимает два ряда с увеличенным отступом контента.
- Исправлены удержание фокуса в модальных окнах, переход из помощника к созданной заявке и горизонтальная прокрутка при смене экранов.
- Убраны неподтверждённые заявления об обучении модели на 150 студентах, точности 87%, полном обезличивании и проверке документа на внешнем университетском сайте.

## Миграции и окружение

1. В Neon выберите базу и ветку из `DATABASE_URL` нужного Vercel-окружения.
2. Выполните **обе** миграции по порядку: `001_student_state.sql`, `002_ai_runtime.sql`. Они используют `IF NOT EXISTS` и не удаляют учебные данные. Если 001 уже выполнена, повтор безопасен.
3. Секреты задаются в Vercel → Settings → Environment Variables, без префикса `VITE_`:

| Переменная | Значение |
| --- | --- |
| `DATABASE_URL` | Pooled TLS URL вашей базы Neon; никогда не публикуйте его |
| `SESSION_SECRET` | Сохраните уже установленный длинный случайный секрет |
| `AI_API_KEY` | Серверный ключ провайдера; существующий действующий ключ можно сохранить |
| `AI_PROVIDER` | `gemini` по умолчанию; `openai-compatible` только для явно выбранного провайдера |
| `AI_MODEL` | Идентификатор модели, доступной вашему ключу, например `gemini-3.5-flash-lite` |
| `ALLOWED_ORIGIN` | Основной адрес сайта, например `https://mgimo-deanery.vercel.app` |
| `AI_GLOBAL_REQUESTS_PER_MINUTE` | Общий лимит приложения, не выше фактической RPM-квоты проекта провайдера; по умолчанию 20 |
| `AI_REQUESTS_PER_MINUTE` | На один аккаунт; по умолчанию 12 |
| `AI_MAX_CONCURRENCY` | Общие одновременные обращения; по умолчанию 2 |
| `AI_QUEUE_TIMEOUT_MS` | Ожидание слота, максимум 10000 |
| `AI_REQUEST_TIMEOUT_MS` | Одна попытка, максимум 25000 |
| `AI_MAX_ATTEMPTS` | Максимум 3 |

Для `openai-compatible` дополнительно обязательны явные `AI_BASE_URL` (HTTPS) и `AI_MODEL`. Провайдер не угадывается по виду ключа; неизвестному шлюзу ключ автоматически не отправляется.

Все серверные экземпляры одного сайта должны использовать одну базу и согласованные лимиты. Раздельные базы Preview и Production имеют отдельные очереди. Если они используют один Gemini-проект, его квота остаётся общей — учитывайте сумму лимитов окружений. API разрешает собственный origin каждого деплоя; Preview не требует выключать проверку origin.

4. Сделайте Redeploy после настройки миграций и переменных. Проверьте Preview, затем объединяйте ветку с main.

Очередь сглаживает нагрузку, но не увеличивает квоту Gemini. Повторы не исправят исчерпанную дневную квоту, ограничения модели или доступа ключа. Конкретный тариф и доступность модели проверяются у провайдера.

## Проверки

```bash
npm ci
npm run lint
npm run typecheck:api
npm run build
npm test
```

По умолчанию тесты используют память и mock ответов ИИ. Для реального PostgreSQL задайте `DATABASE_URL` **отдельной тестовой базы**, предварительно выполните обе миграции, затем:

```bash
npm test
npm run test:ai:shared
```

Не запускайте эти тесты на базе конкурсного сайта: они создают и сбрасывают состояние демо-аккаунта Алексея. `test:ai:shared` проверяет две отдельные Node-программы, использующие общий слот PostgreSQL.

Браузерная проверка поднимает локальные Vite и API на портах 5173 и 3001. Освободите эти порты:

```bash
npx playwright install chromium
npm run test:browser
```

Скриншоты сохраняются во временную папку ОС (либо в `SMOKE_SCREENSHOTS`). Тест проходит 360/430/1280 px, вход, заявку, этапы, клавиатуру, язык, доступность и изоляцию двух браузерных контекстов. Ответ ИИ в браузерном тесте подменён, чтобы проверка не тратила ключ и не зависела от квоты.

В текущем пакете PostgreSQL проверен локально на настоящем сервере; это не подтверждение доступа к вашей Neon из Vercel. Живой Gemini без вашего серверного окружения не проверен. Полное соответствие WCAG не заявляется.


## Проверка модели по официальной документации

Старый gemini-2.5-flash ограничен для новых пользователей; Google объявил автоматическую маршрутизацию на gemini-3.5-flash-lite с 1 декабря 2026. В примере и fallback пакета используется gemini-3.5-flash-lite. Уже установленная AI_MODEL не переписывается кодом: укажите доступную вашему ключу модель в Vercel. У Gemini удалён устаревший temperature; последний ход запроса должен быть пользовательским.
