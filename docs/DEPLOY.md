# Деплой на Vercel + Neon

1. Импортируйте репозиторий `KusuoSaik/mgimo-deanery` в Vercel. Preset: Vite; Build: `npm run build`; Output: `dist`.
2. Подключите Neon к Production и Preview. Внешние Auth и Realtime этому прототипу не требуются. Если используете Custom Prefix, код всё равно должен получить переменную `DATABASE_URL`.
3. Выполните `migrations/001_student_state.sql`, затем `migrations/002_ai_runtime.sql` в базе/ветке, на которую указывает `DATABASE_URL`.
4. Добавьте серверные переменные из `.env.example`. Точный перечень и смысл лимитов — в [UPGRADE_SETUP.md](UPGRADE_SETUP.md). Ключи и URL с паролем не должны иметь префикс `VITE_`, попадать в код или Git.
5. Redeploy Preview. Пройдите сценарии под двумя демо-аккаунтами, создайте заявку, выйдите и войдите снова. Проверьте ответ ИИ по реальным серверным логам и реальной квоте провайдера.
6. После проверки объедините ветку с main. Production должен получить обе миграции и серверные переменные до публикации обновления.

Для локальной работы: `npm ci`, скопируйте `.env.example` в `.env`, затем `npm run dev`. Без DATABASE_URL локальная память теряет состояние при перезапуске; в production отсутствие базы вызывает 503. Локальная `.env` загружается до создания соединений с базой.
