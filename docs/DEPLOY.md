# Деплой конкурсной версии

## Vercel

1. Откройте Vercel и импортируйте `KusuoSaik/mgimo-deanery` или загрузите архив.
2. Выберите пресет **Vite**.
3. Укажите команду сборки `npm run build` и каталог `dist`.
4. Добавьте переменные окружения:

```text
SESSION_SECRET=<случайная строка не короче 32 байт>
ALLOWED_ORIGIN=https://<ваш-домен>.vercel.app
AI_API_KEY=<ключ провайдера, если нужен живой ИИ>
AI_MODEL=gemini-2.5-flash
AI_REQUESTS_PER_MINUTE=12
AI_MAX_CONCURRENCY=2
AI_QUEUE_TIMEOUT_MS=10000
AI_REQUEST_TIMEOUT_MS=25000
AI_MAX_ATTEMPTS=3
```

`SESSION_SECRET` обязателен для Vercel. При его отсутствии auth-функции специально завершаются с ошибкой, чтобы сайт не работал с тестовым секретом.

Ограничители ИИ хранят счётчики в памяти процесса. Для конкурсного прототипа это защищает каждый работающий экземпляр; для строгого глобального лимита между несколькими serverless-инстансами потребуется общее хранилище Redis/KV.

## Локальная проверка

```bash
npm install
cp .env.example .env
npm run dev
```

В `.env` оставьте `ALLOWED_ORIGIN=http://localhost:5173` и задайте любой длинный локальный `SESSION_SECRET`. Не добавляйте `.env` в Git и не публикуйте `AI_API_KEY`.

Проверка:

```bash
npm run lint
npm run typecheck:api
npm run build
```

## Приёмка перед отправкой

- войти под Алексеем и открыть профиль, расписание, БРС и заявки;
- войти под Дмитрием во втором приватном окне и сравнить данные;
- создать заявку в первом окне и обновить страницу;
- проверить, что заявка не появляется в кабинете Дмитрия;
- проверить экран шириной 360 px;
- убедиться, что в настройках Vercel задан `SESSION_SECRET`, а AI ключ не находится в GitHub.

Если ключ уже был показан в переписке или попал в логи, его нужно отозвать у провайдера и создать новый перед публикацией.
