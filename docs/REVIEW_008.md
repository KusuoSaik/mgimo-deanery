# Повторная проверка — пакет 008

16 ноября 2026. После git fetch origin актуальный origin/main остался на 70096ef5645868afdfaa39c830984bfa6dab8be9. Нового опубликованного проекта не обнаружено. Проверена локальная версия пакета 007 (917061e), подготовленного в предыдущем этапе.

## Найденные и исправленные проблемы

1. Экспорт .ics не закрывал VCALENDAR. Это ошибка предыдущей ИИ-доработки: тест проверял наличие событий и часового пояса, но не целостность документа. Добавлен END:VCALENDAR. Регрессионный тест проверяет стек вложенности компонентов и окончание как непустого, так и пустого календаря. Браузерный тест проверяет окончание реально скачанного файла. Импорт в сторонние календарные приложения отдельно не проверялся.
2. Демо-отметка посещаемости утверждала, что проверяет геопозицию и записывает посещение. Фактически она проигрывала таймер. Тексты RU/EN теперь явно описывают демонстрацию без геолокации и записи; пользователь предупреждён о временности локального чек-листа.
3. Калькулятор заявлял «экзамен можно не сдавать» при условном пороге. Теперь он обозначен учебной моделью, а правила предлагается уточнить у преподавателя.

Инструменты этапа: Codex/ChatGPT (аудит, код, тесты, документация), Git (получение актуальных refs, патч), Node/npm/TypeScript/ESLint/Vite (проверки), Playwright/Chromium (браузер), Python (упаковка). Другие модели и интервью не использовались.

Фактическое поручение: повторно проверить новый проект, улучшить его и передать код с промптом для Cursor. Рабочая постановка по итогам аудита: проверить не только скачивание, но и структурную корректность календаря; сопоставить обещания интерфейса с реальными действиями кнопок. Этот текст — описание процесса, не вымышленная стенограмма.

Пакет содержит накопительный патч к текущему origin/main и отдельный патч только 008 к 917061e. Выбирается один патч в зависимости от применённой версии; не применять оба подряд.
