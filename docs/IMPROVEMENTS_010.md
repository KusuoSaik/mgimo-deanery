# Надёжность при сбоях — пакет 010

База: 23a94c8, пакет 009. Работали с локальной подготовленной версией.

## Изменения

- Общий requestJson для авторизации, состояния студента и кабинета сотрудника ограничивает ожидание 20 секундами, включая чтение тела ответа. Раньше зависший fetch мог удерживать кнопки и всю SessionWork-очередь без ограничения. Отмена при смене аккаунта сохранена.
- Тайм-аут не вызывает автоматическую повторную отправку POST: сервер мог уже сохранить операцию. Сообщение просит обновить данные перед повтором. Это не гарантирует отсутствие дублей при ручной повторной отправке без обновления; постоянный клиентский журнал операций не добавлялся.
- Ошибки прокси с HTML вместо JSON и сбои сети показываются понятным текстом RU/EN. Ответ 200 с невалидным JSON больше не трактуется как успешный logout или отсутствие сессии.
- Ошибка отправки заявки теперь внутри открытого диалога с role=alert, а введённые поля сохраняются. Раньше общий alert находился за модальным окном и inert-корнем, поэтому его было трудно увидеть и прочитать скринридером.
- Очистка истории чата отражается на экране только после подтверждения API. Ошибка очистки больше не удаляет видимую историю локально.

## Проверки

Новые регрессии: зависший запрос и зависшее тело, восстановление очереди после тайм-аута, отсутствие автоматического повтора записи, отмена пользователем, HTML/JSON-ошибки, сбой сети, передача Headers. Браузерный сценарий принудительно возвращает 503 при создании заявки, проверяет alert внутри формы и сохранённый заголовок, затем повторяет успешно.

ИИ-провайдер в тестах подменяется, локальное хранилище — memory adapter. Серверная схема и SQL не менялись. Истечение сессии по-прежнему сообщает о необходимости нового входа; автоматический перенос незавершённого ввода между сессиями не реализован. Production и доступ из России в этом этапе не проверялись.

Использованы Codex/ChatGPT для кода, ревью и документации; Git, Node/npm/TypeScript/ESLint/Vite и Playwright/Chromium для проверки; Python для упаковки. При сборке обнаружена несовместимость parameter property с erasableSyntaxOnly; поле ApiError.status объявлено явно и сборка повторена.

Результат: lint, типизация API, сборки клиента/сервера и npm test прошли. Chromium прошёл сценарии 360/430/1280, включая принудительную ошибку формы 503 и успешный повтор. После ревью дополнительно исправлено объединение Content-Type без учёта регистра; отдельный тест подтверждает отсутствие дубля заголовка. Проверка серверных сценариев выполнялась на memory adapter; PostgreSQL в этом этапе не перезапускался.
