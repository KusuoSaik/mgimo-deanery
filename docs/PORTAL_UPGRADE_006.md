# Обновление 006: завершённые сценарии кабинета

База: `21efffea78eb3651fdcace620c5f33a1a4ca3ba4`. Дата: 15 ноября 2026 года.

## Что изменено

- Студент не переключается в деканат. Серверный аккаунт сотрудника открывает отдельную очередь; `/api/staff` проверяет роль по подписанной сессии. Студенческие `advance_demo_request` и `update_request` теперь возвращают 403.
- Сотрудник видит только необходимые для работы вымышленные имя, группу, заявки и историю обращений. Паспорт, СНИЛС и чат студентов не возвращаются этой ручкой.
- Карточка приоритетов показывает до трёх дел: уточнения, недостаток баллов до явно обозначенного учебного порога, готовый документ, консультация, перенос ближайшей пары или просроченная оценка срока. Ссылки открывают нужную заявку или дисциплину.
- Итоговые результаты аттестации заданы отдельно от баллов БРС. Для каждого предмета доступны семестр, результат, дата; у двух долгов — демонстрационные даты пересдач. Произвольное прибавление к GPA удалено.
- Консультации сохраняются в состоянии владельца на сервере, переживают повторный вход. Даты генерируются на будущие рабочие дни по МСК, повторная запись и пересечение времени проверяются сервером. Это демо-запись, реальные преподаватели не уведомляются.
- Заявка содержит оценку готовности (три рабочих дня), историю, комментарий сотрудника, состояние «Нужно уточнение» и ответ студента. Отмена доступна до начала обработки. Проверка revision предотвращает устаревшие обновления. Сотрудник обновляет очередь кнопкой «Обновить»; студент — «Обновить данные» или перезагрузкой страницы. Автоматическая доставка push не заявляется.
- Скачивается настоящий PDF с встроенной кириллицей; номер и дата привязаны к заявке. Название заявки сохраняется, а содержимое честно обозначено как демонстрационный результат обработки. Подпись имитируется. Макет не заменяет официальную справку, характеристику, решение о матпомощи или ЭЦП.
- В профиль добавлено направление подготовки. Новые контролы доступны в RU/EN; названия предметов и вводимые пользователем тексты сохраняют исходный язык.
- Ответы ИИ дополнены переходами для проверки учебных данных. Эти кнопки являются навигацией, а не доказательством, что генерация ИИ использовала конкретный источник.
- Удалены открытые пароли из React-компонента входа и устаревшая клиентская псевдохеш-функция. Для демо-входа пароль вводится вручную из README. На сервере проверяется scrypt-хеш.

## Данные и деплой

`src/types.ts` не изменяется. Дополнительные контракты находятся в `src/portalDomain.ts` и расширениях `StoredAccount`. Новые поля `requestDetails` и `consultations` добавляются в прежний JSONB `student_state.data`. Старые записи читаются с безопасными значениями по умолчанию; отдельная SQL-миграция не нужна. Существующие миграции 001/002 и DATABASE_URL остаются необходимыми для production. Без базы локальная память теряется после остановки сервера.

1. Применить пакет установщиком или проверенным git patch.
2. Выполнить `npm ci`, затем команды проверок ниже.
3. Проверить существующие DATABASE_URL, SESSION_SECRET, ALLOWED_ORIGIN на Vercel; значения не копировать в код или чат. Дополнительные ключи для этого пакета не нужны.
4. Задеплоить через обычный Git/Vercel-процесс владельца.
5. На опубликованном адресе пройти все три роли. Создать заявку в аккаунте студента, уточнить и довести до готовности сотрудником, обновить данные студента и скачать PDF. У другого студента этой заявки быть не должно.
6. Проверить открытие из России без VPN отдельно. Среда разработки не подтверждает доступность Vercel из России и работу до 28 ноября.

Деплой, опрос студентов, работа живого ИИ и проверки на пользовательской Neon не входят в автоматически подтверждённые результаты этого пакета.

## Команды проверок

```sh
npm run lint
npm run typecheck:api
npm run build
npm test
npx playwright install chromium --only-shell
npm run test:browser
```

При установленном системном Chromium можно задать BROWSER_EXECUTABLE_PATH. Параметры BROWSER_ARGS — JSON-массив; они предназначены для тестовой среды. Проверка браузера использует localhost:5173 и :3001; их нужно освободить. Для проверки базы используйте только отдельный тестовый DATABASE_URL: тесты сбрасывают вымышленные данные демо-аккаунтов.
